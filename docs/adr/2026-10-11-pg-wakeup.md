# PostgreSQL 事务唤醒与主动对账基础设施

状态：用户已批准 LISTEN/NOTIFY + 主动 DB 对账方案；本 ADR 仅实现独立基础模块，接入由协调 Agent 完成。无 schema、迁移或额外服务变更。

## 接口与接入

`app.chat.pg_wakeup.PgWakeup(database_url)` 每 Hub lifespan 创建一次。
`await start(on_wakeup, on_reconcile)` 启动后台任务，立即返回，不代表 PG 已连接；重复 start 幂等。
`on_wakeup(WakeupHint(kind, id))` 与 `on_reconcile()` 是可取消的 async 回调，串行运行且有超时；各自创建短生命周期 DB session，按当前权限和持久游标对账。回调不可共享 listener 或请求 DB session，不可将通知当作 WS 消息/执行授权。
`await stop()` 立即取消连接、退避、回调和后台任务，并有界关闭专用连接；同一对象可重新 start。默认参数：10 秒周期对账、5 秒连接/IO/回调超时、0.25–10 秒重连退避、256 个待处理不同 hint、1 秒连接关闭超时。

协调者在 `main.py` lifespan 中创建并 start，关闭时先 stop 唤醒模块，再关闭其下游对账器。
在 `ws_handler.py` 创建投递/进度/结果、`delivery_service.py` 取消/租约变化、`a2a/task_manager.py` 状态变化的原有业务事务内，按真正受影响的 agent/user/room ID 调用 `await signal_in_transaction(session, kind, id)`，然后由原调用者 commit。必须在提交前调用；模块不创建独立发布连接、不 flush/commit/rollback。业务事务必须已开始，PG autocommit 被拒绝。

## 事务与故障行为

固定频道 `mapr_wakeup_v1`；发布只有绑定参数 `SELECT pg_notify(:channel, :payload)`。专用 asyncpg 连接不借用业务连接池，不打开长事务；`add_listener` 的 LISTEN 在独立隐式事务结束后生效，然后执行一次完整 catchup，成功后才处理排队通知。catchup 失败重试，不开启通知派发。

通知仅 `{v:1, kind:agent|user|room, id:...}`，ID 为 1–128 个 ASCII 标识符字符，无正文/令牌/URL/事件内容。合法 ID 仍属非可信 hint，不证明账号、权限或对象存在。频道对同 DB 用户可见，不承诺通知机密性。错误日志固定文本，不记录 DSN、异常详情或通知。绑定参数阻止 SQL 注入，但调用者仍必须传真实 ID，不可将秘密伪装成 ID。

重复 hint 在待处理期间合并，队列满时丢弃 hint 并请求全量对账；持续通知不能阻断周期对账。连接失败有界指数退避，掉线终止回调/健康检查触发重连；每次 LISTEN 后再次 catchup。掉线、无通知、重复通知及 SQLite 均定期全量对账。SQLite 不连接 PG、不执行 pg_notify。

NOTIFY 随业务 COMMIT 才可见，ROLLBACK/SAVEPOINT rollback 不会发出；PG 可合并同一事务内重复通知。发布失败使业务事务失败，由调用者 rollback；不可吞掉失败后宣称已持久交付。数据库队列满也可能使 COMMIT 失败。无 exactly-once 或即时交付承诺，恢复正确性依赖协调者的持久游标、分页对账、权限复核与 CAS fencing。

## 验证边界

本机无 PostgreSQL 服务端/集群工具，禁止使用真实数据库。测试使用确定性 fake PG 连接/事务和隔离 SQLite；覆盖 LISTEN/catchup 顺序、独立连接、重复/溢出、断线/重连/半开健康检查、失败隔离、周期对账、停止释放、绑定 SQL 和事务提交/回滚模型。fake 不能证明真实 PG 的事务通知或真实跨 Hub 网络行为，集成后仍须临时 PG + 双 Hub 故障验收。

SQLAlchemy 2.x 的 `Connection._is_autocommit_isolation()` 是当前已 inspect 的内部 API，用于同时拒绝连接 execution_options 与 engine 默认 AUTOCOMMIT。升级 SQLAlchemy 时须重新核查；错误不得绕过事务校验。自定义 connect_factory 必须返回专属、空闲的 asyncpg Connection，已有事务的连接被拒绝并关闭。回调必须协作取消；阻塞事件循环或吞掉取消的回调无法由 asyncio 物理强制终止。

依据：[PostgreSQL LISTEN](https://www.postgresql.org/docs/current/sql-listen.html)、[NOTIFY](https://www.postgresql.org/docs/current/sql-notify.html)、[asyncpg API](https://magicstack.github.io/asyncpg/current/api/index.html)。
