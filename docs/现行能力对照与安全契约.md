本文替代历史拼接稿 [整合-评估报告与全部实施计划.md](./整合-评估报告与全部实施计划.md)，按代码与验证记录汇总当前工作区能力、数据库迁移、协议契约及明确排除项。

## 1. 架构红线与明确排除项

1. **本机 worker 是唯一决策与执行权威**：私钥、凭据（`0600`）、`rulesEngine` 裁决、连接器 `execute()` 及动作审批全部在本机成员进程（`workers/xmtp-member`）运行；Hub 只负责身份、房间、席位、邀请及安全元数据控制面。
2. **严禁明文进 Hub**：XMTP 加密房间的聊天正文、邮件正文、附件正文、知识库正文、动作原始参数与私钥不得写入 Hub 数据库、日志或异常；`transport="xmtp"` 房间的 `files`、`knowledge` 与 `approvals` 明文写入已统一返回 `409 body_not_on_hub`。
3. **远端永不放权**：Hub 下发的 `house_rules` 或模板建议中任何 `"allow"` 在 worker 边界一律降格为 `"ask"`；`"cannot"` 允许远程收紧；有效裁决优先级为 `硬禁区 > 本机 actor 覆盖 > 本机 house 覆盖 > Hub 建议 > 出厂默认(ask)`。
4. **至多一次执行 + 不确定可对账**：外部写动作在 `execute()` 前落盘意图并写入 `X-MAPR-Request-Id`；超时/崩溃/5xx 收敛为 `uncertain`，**绝不自动重试**；回执失败仅重发持久化信封（Grant 过期时以同一不可变结果重签）。
5. **明确不做清单**：支付、银行账户、Strava、密码/银行卡托管、通用全量导出的 `data.export_all` 全部处于硬禁区（`rulesEngine` 与 Hub 校验双层拒绝）；不改为托管密钥架构。

## 3. 协议与数据库契约速查

- **MAPR1 信封新增类型**：`action_request`（含 `action`/`params`/`purpose`，进入 `actionSchemas` 校验）、`action_result`（携带 `grant`、`params_hash`、`status`、`receipt`、`summary` 与 `result_signature`）、`member_revoked`（仅当 `conversation === activeGroupId` 且 `sync()+members()` 确认缺席时触发会话级撤销）。
- **规范哈希**：worker `canonicalStringify`（递归排序键、丢弃 `undefined`）与后端 `json.dumps(..., sort_keys=True, separators=(",", ":"), ensure_ascii=False)` 对齐；`Grant` 的 `payload_hash` 与出站登记 `params_hash` 同源。
- **Gmail 幂等与对账**：RFC822 原文带 `X-MAPR-Request-Id: <request_id>`，供 `uncertain` 状态下通过 Gmail Sent 人工核对。
- **Alembic 链头**：`k10c20261118` → `l20c20261120`（m1：席位/邀请/人类地址/`rooms.settings_json`/`room_invite_redemptions`/`xmtp_auth_nonces`）→ `m30c20261120`（m2：`activity_events`、`activity_checkpoints`，无正文或 `params_hash` 列）。
