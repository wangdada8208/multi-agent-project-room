# 总路线与执行规则

> 这是完成整个项目的入口文档。任何代理（包括能力较弱的模型）接手时，先读完这一份，再打开下面列出的阶段计划。

## 1. 评估报告能不能直接交给较弱的模型实现？

不能。`docs/评估报告-对标AgentPicnic与架构演进方案.md` 是一份评估和提案，适合人类做决定，不适合照着写代码。它缺三样东西：

1. **没有逐行代码和测试。** 报告只说"成员进程加发送者白名单""定义内容类型"，没有写函数名、参数、返回值和测试断言。较弱的模型会自己发明接口，前后对不上。
2. **没有运行命令和预期输出。** 执行者无法判断自己做对了没有。
3. **有未验证的假设。** 写报告时没有发现"另一方的浏览器和成员进程没人拉进群"。按报告做，双机演练必然失败。

所以另外写了下面这套计划。

## 3. 执行规则（每一条都必须遵守）

1. **一次只做一个任务。** 按计划里的 Task 编号顺序做，不跳，不合并。
2. **每一步都要执行并对照 Expected。** 输出和 Expected 不一致时，不要继续下一步。
3. **先测试后实现。** 计划要求"运行，确认失败"的步骤不能省。它证明测试真的在测新东西。
4. **代码照抄。** 计划里给了完整代码的地方，一个字符都不要改，包括注释和空行。
5. **只改计划里列出的文件。** `Files:` 之外的文件不要碰。
6. **每个任务结束都提交**，提交信息照计划里写的格式，这是 `AGENTS.md` 第 6 节的要求。
7. **勾选进度。** 每完成一步，把计划文件里对应的 `- [ ]` 改成 `- [x]`，随该任务一起提交。下一位接手的人靠这个知道做到哪了。
8. **不要把密钥、地址、群 id、令牌、`.env`、`.state/` 目录写进 git、提交信息或聊天。**

## 6. 名词解释

| 名词 | 意思 |
| --- | --- |
| Hub | `backend/` 里的 FastAPI 服务。管账号、房间、成员、群绑定。加密房间的聊天内容它读不到 |
| 成员进程 / 主人网关 | `workers/xmtp-member`。跑在每个主人自己的电脑上，持有 XMTP 私钥，替主人收发和把关 |
| XMTP | 端到端加密的消息网络。`dev` 是测试网络，可以随便用；`production` 是正式网络 |
| 群 / group | XMTP 里的一个加密群聊。Hub 房间通过 `xmtp_group_id` 对应一个群 |
| 白名单 | `XMTP_ALLOWED_SENDERS`。只处理这些地址发来的消息 |
| 策略 | `.state/policy.json`。谁能向我申请哪类数据 |
| 同意队列 | `.state/consents.json`。等主人批准的申请 |
| 授权 / Grant | 主人批准后签发的单次凭据，10 分钟有效，绑定接收人和数据哈希 |
| 账本 | `.state/ledger.jsonl`。只记"什么时候、和谁、发生了什么"，不记内容 |
| 控制台 | 成员进程在 `http://127.0.0.1:8787/` 提供的网页 |
| MAPR1 | 群里结构化消息的前缀 |

## 7. 常见问题排查

| 现象 | 原因与处理 |
| --- | --- |
| `Cannot find module '.../xxx.ts'` | 还没创建该文件，或文件名大小写不对。对照计划的 `Files:` |
| 后端测试 `ModuleNotFoundError` | 没用 `.venv` 里的 Python。用 `../.venv/bin/python -m pytest` |
| `npm run typecheck` 报 `allowImportingTsExtensions` | `package.json` 的 `typecheck` 脚本没照抄。见阶段 A Task 6 Step 1 |
| 成员进程启动报 `XMTP_ALLOWED_SENDERS is empty` | 这是故意的。在 `.env` 里填至少一个地址 |
| 成员进程启动报 `EADDRINUSE` | 端口被占用。换 `OWNER_NOTES_PORT`，或关掉上一个成员进程 |
| 日志 `group ... not found locally` | 这个成员还没被拉进群。等已在群里的成员进程补加后重启 |
| 绑定群返回 403 | 当前登录用户不是房主。换房主账号 |
| 绑定群返回 409 | 房间已经绑定了另一个群。这是故意的，不要去改数据库 |
| 控制台 POST 返回 403 | 没带 `X-MAPR-Owner: 1` 请求头，或者不是从 127.0.0.1 访问 |
| 请求发出后对方控制台没有待批准 | 看对方账本：`sender_dropped` 说明你不在对方白名单；`request_denied` 说明对方策略不允许 |
| 批准后对方收件箱为空 | 看对方账本：`disclosure_rejected` 后面的 `reason` 说明了原因；`sender_dropped` 说明批准方不在接收方白名单 |
