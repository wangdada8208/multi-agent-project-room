# XMTP 端到端加密 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**下一位不要从本文件 Task 1 开始。** Task 1 到 Task 8 已在 `feat/xmtp-e2e` 的 `ea1f931` 至 `153267e`。缺口是浏览器没有真正 `sendText`。继续做 `docs/superpowers/plans/2026-09-23-xmtp-member-send.md`。

**Goal:** 让新的加密房间把聊天正文留在 XMTP 群成员端，Hub 只保存 group id，拒绝把这些房间的正文写入 `messages.content`。

**Architecture:** 现有 Hub 房间继续用 WebSocket 明文，直到阶段 4。加密房间由 Node 22 上的官方 `@xmtp/agent-sdk` 成员进程收发。FastAPI 不加入 XMTP group，因此解不开正文。叫醒和轮次在阶段 2 移到成员进程。浏览器在阶段 3 改为成员端收发。

**Tech Stack:** FastAPI、PostgreSQL、Alembic、pytest、Node.js 22、`@xmtp/agent-sdk`、React。

**规格：** `docs/xmtp端到端加密-执行文档.md`

**批准范围：** 可以在功能分支修改代码并跑本地测试。不可以合并 `main`，不可以在生产库执行迁移，不可以把密钥写入 git。

- [ ] **Step 3: Write minimal implementation**

`decideReply` 规则：

- 文本里有 `@` 加上自己的名字，并且名字后面是结尾或非字母数字，则 `reply=true`，`reason="mentioned"`。大小写不敏感。
- 否则当 `participants[turnIndex % participants.length] === selfName` 时，`reply=true`，`reason="turn"`。
- 否则 `reply=false`，`reason="not_this_turn"`。

`index.ts` 在 `text` 事件里先调用 `decideReply`。`reply=false` 时不发送。`reply=true` 时才把解密后的文本交给本进程里的模型或占位回复。占位回复固定为 `收到，本轮由 <selfName> 处理。`，不要把原文回传给 Hub。
