# 同类项目调研：一键接入 Agent / 人机共处加密房间

日期：2026-11-17。目的：对照市面上成熟同类项目，找出可借鉴的设计。
本项目的对应结构：Hub（不读密文）+ 本机助手（配对码绑定账号）+ 席位（每 Agent 一个 XMTP 身份）+ 加密群 + 引擎（本地 CLI 受限环境 / OpenAI 兼容 https / webhook HMAC）。

## 一、最直接对标：Agent Room（agentroom.chat）

开源（MIT）、可自建、建在 **Matrix** 上。一句话卖点和本项目几乎相同：
"Bring any AI agent into your room with one message."

值得借鉴的三扇门设计——按 Agent 能力给三种入口：

| 门 | 适用 | 形态 |
|---|---|---|
| 命令行 | 能跑本地命令的 Agent（配合桌面端） | `agent-room guide` 一条命令领进门，密钥留在本机 |
| MCP | 常驻类 Agent | 挂远程 MCP server `api.agentroom.chat/mcp` |
| 网络 | 什么都不能装的 Agent（如网页里的助手） | 读一份 `agents.txt` 引导文档自己走进来，零安装 |

其他要点：
- **加密诚实分级**：私房间端到端加密；「网络门」进来的 Agent 没有自己的设备密钥，服务器代为持有——房间会**明确标记**这类 Agent「服务器可读」。公共大厅本来就不加密。
- 引导即产品：`agents.txt`/`llms.txt` 放在网站根路径，任何会读网页的 Agent 读文档即可自助加入。
- 我们比他强的一点：每个席位都有自己的 XMTP 密钥（helper 代管、Hub 不可读），没有「服务器代持密钥」这档事。

## 二、BYOA 样板：Cumora（Yetone/cumora，4k+ star，MIT）

人机+多 Agent 的团队聊天（频道/DM/看板/日历），Agent 是一等成员。
`npx cumora agent computer` 在用户机器上起一个常驻守护进程，托管多个 Agent，每个 Agent 有独立 home、记忆、技能。云端每个 Agent 一个 K8s pod，或 BYOA 跑自己机器。**服务器永远不碰用户的供应商密钥。**

可借鉴点：
- **凭证边界**：Agent 用的 `cumora` CLI 只是「argv → 文件 IPC → 守护进程」的桥。守护进程在模型沙箱**之外**持有运行时 JWT、统一 POST `/runtime/cli`。模型生成的命令永远拿不到服务器凭证，也没有任意网络访问。我们的 childEnv 白名单是同一思路的弱化版——目前只限环境变量，没有 IPC 桥。
- **引擎分级**：Claude Code / Codex 是「安全默认」引擎（文件系统、命令网络、子进程凭证三层 fail-closed 边界）；其他引擎要显式 opt-in 才能无沙箱跑——**光在 PATH 里探测到二进制不等于允许执行**。
- **CODEX_HOME 硬链接复用登录态**：把用户个人 `~/.codex/auth.json` 硬链接进隔离运行时，双方共用一份凭证、跟随替换和登出。这正是我们验收时踩到的坑（探测到 ≠ 有登录态）的成熟解法。
- `COORDINATION.md`：多引擎共处一房不互相打架的协调经验，值得细读。

## 三、人类+Agent 的 Slack：agentes-chat（1.7k star，AGPL）

Agents 是 workspace 正式成员：有角色、有 owner、有**每月预算**（每次调用前检查）、有自己的电脑和浏览器、MCP 工具。
- **审批门**：合并、部署、任何标记敏感的操作，必须等真人在聊天里批准。
- **路由器**：没人 @ 的消息进路由器——先代码筛候选，再小模型决定谁接。
- 每次模型调用按 Agent 记账。

## 四、本地多 Agent 聊天室：agentchattr（1.6k star，MIT）

本地聊天服务器，@ 提及时自动往对应 Agent 的终端（tmux）注入 prompt；Agent 之间也能互相 @ 唤醒。
- **防失控护栏（loop guard）**：Agent 互相点名连锁到 N 跳后自动暂停，**人类消息永远放行**，`/continue` 恢复。这是对我们 turnPolicy 的直接补充——目前我们没有显式的「连环对话上限」。
- 会话模板：开局给每个 Agent 发固定角色说明。

## 五、配对与加密参考：Happy（slopus，MIT）

手机遥控本机 Claude Code/Codex，端到端加密中继。
- **配对**：电脑端显示一次性公钥二维码 → 手机扫 → 手机把账号公钥加密回传 → 之后每会话一把随机密钥。中继只见密文。
- 守护进程模式：CLI 退出后后台 runtime 还在，手机随时接管会话。
- 对应我们：配对码 → 可升级为二维码；helper 已常驻，方向一致。

## 六、网关姿态参考：OpenClaw（开源基金会托管）

本机网关 + 各聊天渠道。值得抄的是**监听面纪律**：
- `bind` 默认 loopback；可选 lan / **tailnet** / 自定义 IP；非 loopback 必须配 auth token。
- 每个渠道 `allowFrom` 白名单，绝不裸奔。
- "trusted gateway, untrusted execution, policy enforced by code" 与我们「Hub 不读密文、helper 做边界」同构。

## 七、外围参考

- **Claude Squad / Vibe Kanban / VibeTree / ccmanager**：本地多 CLI 编排，核心是「每个 Agent 一个 git worktree + 独立 PTY」。如果项目房间要落到真实代码协作，worktree-per-seat 是成熟做法。
- **Matrix 生态**（Agent Room 的选择）：E2E 群聊 + 机器人是成熟路径；我们选 XMTP 拿到了钱包身份和「无服务器代持密钥」，但 Matrix 的设备验证、交叉签名经验可在需要时参考。

## 八、可借鉴清单（按性价比排序）

| # | 借鉴项 | 来源 | 对现状的增益 | 量级 |
|---|---|---|---|---|
| 1 | **消息连环护栏**：Agent 互 @ 连锁 N 跳即暂停、人类永远放行、/continue 恢复 | agentchattr | 防多 Agent 失控刷群，补上 turnPolicy 缺的维度 | 小 |
| 2 | **Agent 信任分级标记**：本地 CLI / 云端 API / webhook 在房间里显式标出信任级别 | Agent Room | 用户知道每条回复的可信边界 | 小 |
| 3 | **CODEX_HOME 类凭证复用**：硬链接/跟随替换复用个人登录态 | Cumora | 直接解决「探测到≠能登录」的验收坑 | 中 |
| 4 | **agents.txt 自助引导**：Hub 根路径放机器可读加入指南 | Agent Room | 会读网页的 Agent 零安装进门，「一条消息接入」的轻量门 | 小 |
| 5 | **MCP 远程门**：把「加入房间/读/发」封装成 MCP server | Agent Room | Claude Desktop 等不装 helper 也能进房 | 中 |
| 6 | **每席位预算 + 敏感操作审批** | agentes-chat | 成本可控、危险动作有人卡 | 中 |
| 7 | **凭证 IPC 桥**：模型子进程不持任何服务端凭证，argv 桥接 | Cumora | 比 childEnv 更彻底的边界 | 中 |
| 8 | **二维码配对** | Happy | 安装向导 UX 升级 | 小 |
| 9 | **tailnet 绑定模式** | OpenClaw | 用户把 helper 放 VPS 的正经姿势 | 小 |
| 10 | **worktree-per-seat** | Claude Squad | Agent 真正动代码时的隔离 | 大（后续 WP） |

## 九、我们已经有、且做对了的

- 每席位独立 XMTP 身份 + 真端到端加密（Agent Room 的「网络门」做不到这点）；
- helper 只绑 loopback；
- webhook 引擎 HMAC 验签；
- 敏感环境变量白名单 + Codex bwrap；
- owner/member/viewer 角色门禁。
