## 已批准的兼容扩展

1. **按范围保存请求约束**：`DateRange` 扩展可选 `query`，email.receipt 必须含非空 query；构造/编解码/队列/Grant 全链保留 query。旧日历 Grant 无 query 时签名串保持原样；邮件签名绑定 query，避免批准后改查询。
2. **成员任务可靠状态**：TaskStore 增加 conversation_id、current_round；增加执行侧持久化 `(sender, conversation, request_id, round)` 去重记录。只接受派发目标、所在会话、当前轮次的结果，终态不再接受结果；第三轮拒绝及模型裁决解析失败直接升级。重试 task 可选 challenge。旧任务无会话记录时拒绝不明确的远端结果并提示重新派发。
3. **取消接口**：增加 MAPR1 `task_cancel` 信封（request_id、to）、本机 `POST /api/tasks/:id/cancel`。收到取消时即时 AbortController 中止正在等待的模型 fetch；复核持久终态并丢弃迟到结果。成员进程保持独立的接收/执行，不依赖模型自愿遵守取消。
4. **自助接入**：基于现有 room_invites 表，兑换要求新身份签名，兑换保持原地址可重试。网关本机新增受保护的邀请批准操作，验证 Hub 返回的兑换状态与 group id，再以房主群身份实际 addMembers，成功后原子更新 policy/allowlist；CLI 提供 join 命令完成兑换并读取真实状态。私钥留本机，不由 Hub 加人或解密。无新数据库表。
5. **Connect 单次申请**：授权页面创建绑定 app_id、scope、constraints、callback_origin、state/redirect_uri 的本机持久待批准申请，approve/deny 按 request_id 原子消费。popup postMessage 指定调用方来源；客户端校验 origin/source/state/签名/哈希/范围/有效期。结果 grant 仍只允许 calendar.free_busy/email.receipt；不开放外部写操作。
