### 3.1 关于第 5 项检查 `test`（deploy.yml）

10-19 建议里还列了 `deploy.yml` 的 `test`。核对 `deploy.yml` 的触发器：

```yaml
on:
  push:
    branches: [main]
  workflow_dispatch:
```

`deploy.yml` **没有 `pull_request` 触发器**，所以 `test` 这个检查名只出现在 push / 手动运行上，永远不会出现在 PR 上。若把它写进 PR 必需检查，所有 PR 都会永久停在「Expected — Waiting for status to be reported」，反而无法合并。因此本次**没有**把它加进 `contexts`。

`test` 的门禁作用由工作流内部的作业依赖结构化保证，无需分支保护：`build.needs = test`、`deploy.needs = build`。真实运行证据见第 4 节：push 触发的运行里 `test` 成功后 `build` 才成功，`deploy` 因 `if` 被跳过；2026-10-19 首次发布失败的运行 `39183543117` 中 `test` 成功、`build` 成功、`deploy` 失败并自动回滚，生产未变。
