## 2. 做了什么

### m1 结构迁移 `l20c20261120`（`backend/alembic/versions/l20c20261120_m1_seats_invites_rules.py`）

- `agent_seats`：`helper_id` 改可空；新增 `source`（'helper'|'invite'）与 `paused_at`；新增部分唯一索引 `uq_agent_seat_invite (room_id, agent_user_id) WHERE helper_id IS NULL`（云端席位每人每房一席，不影响 helper 席位原有唯一约束）。
- `room_invites`：`max_uses` / `use_count` / `requires_approval` / `role` / `revoked_at`；CHECK `role IN ('member','viewer')`、`use_count BETWEEN 0 AND max_uses`。
- `room_permissions`：`xmtp_address` + 索引 `ix_room_permissions_xmtp`。
- `rooms`：`settings_json` + `settings_version`。
- 新表 `room_invite_redemptions`：逐次核销审计（kind/status/redeemer/agent/seat/decider/TTL/approved_scopes），唯一索引 `(token, redeemer_address)`。
- 新表 `xmtp_auth_nonces`：域名隔离、单次使用 EIP-191 挑战，行级原子核销，重启不丢。
- 全部用 `batch_alter_table` + `sa.JSON()`，SQLite 与 PostgreSQL 同一代码路径执行。

### WP5 席位生命周期

- `POST /api/v1/rooms/{room_id}/seats/{seat_id}/pause` 与 `resume`：房主或席位主人可调用；暂停只停进程不删席位，恢复只清显式暂停；已移除席位返回 409。
- `HeartbeatResponse` 新增 `seats_to_pause`（与 `seats_to_stop` 严格分离，stop 列表只放 removed 席位）与 `rooms`（含 `settings_version`/`settings_json`，供 helper 同步）。
- `mark_group_added` 允许房主或席位主人。
- 云端 Agent 自助：`GET /api/v1/agent-seats/{seat_id}`（agent JWT `sub == seat.agent_user_id`；被移除后仍可读，便于 fail-closed 检测）、`POST /api/v1/agent-seats/{seat_id}/token`（已移除席位返回 409，不发新令牌）。
- `DELETE /api/v1/rooms/{room_id}/members/{user_id}`：若目标是 Agent 用户，同事务退役其活跃席位；成员列表透出 `xmtp_address`。
- `PUT /api/v1/rooms/{room_id}/members/me/xmtp-address`：EIP-191 签名 + 单次 nonce 绑定人类 XMTP 地址（拒绝伪造/重放/过期）。

### WP6 可复用邀请与云端注册

- `POST /api/v1/invites/nonce`：签发域名隔离单次 nonce；`app/core/eip191.py` 验签时**从存储行重建签名文本**（action/resource/address/expiry 不受客户端字段影响），行级条件 UPDATE 原子核销。
- `POST /api/v1/rooms/{room_id}/invites`：owner-only；`max_uses` 1..32；`role` 仅 member|viewer（owner → 422）；`proposed_scopes` 拒绝硬禁前缀（`payment.` `banking.` `credentials.` `password.` `card.` `wallet.`）与 `data.export_all`。
- `DELETE .../invites/{token}`：置 `revoked_at`（不物理删除），同事务把 pending 核销级联为 revoked；单次邀请已核销返回 409 保留审计。
- `GET /api/v1/invites/{token}`：`remaining_uses`/`requires_approval`/`role`/`revoked_at`。
- `POST /api/v1/invites/{token}/redeem`：必须 EIP-191 + nonce；地址占位式请求 422。容量用原子条件 UPDATE（`use_count < max_uses AND revoked_at IS NULL AND expires_at > now`，按 rowcount 判定）。/accept 先付容量的人类在 /redeem 只做验签绑定、不二次扣槽。
- `POST|GET /api/v1/invites/{token}/agent-register`：验签后创建/复用 Agent 用户 + `RoomPermission` + `AgentSeat(helper_id=NULL, source='invite', agent_key='ext:<redemption>')`；`requires_approval=True` 时 pending，不发令牌、不同步组，GET 轮询只在批准后首次发放 agent_token。
- `GET .../redemptions` + `approve` / `deny`：owner-only；`approved_scopes ⊆ proposed_scopes` 且过硬禁过滤；批准时原子消耗容量；pending 不占 `use_count`（每 token 上限 64）。
- `PATCH /api/v1/rooms/{room_id}/settings`：owner-only；仅安全元数据（JSON 可序列化、≤8 KiB、递归禁 scope），`settings_version` 自增。

## 4. 关键正确性核验点

- 未签名/异地址签名/跨 token nonce → 422；同一 nonce 重放 → 409；nonce 在成功路径必然烧掉（含幂等返回路径）。
- pending 不占 `use_count`；revoke 级联 pending→revoked；approve 超发 scopes 或非子集 → 422。
- `/accept` 已改为原子条件 UPDATE 扣容量（修掉了初版"只查不扣"的绕账漏洞）；同一人 accept→redeem 只算一席。
- 移除 Agent 成员同事务退役席位；被移除云端 Agent 可读自身状态但 `token` 续期 409。
- 设置接口拒收含禁 scope 的元数据，`settings_version` 每次 +1。
- 无聊天/邮件正文、无私钥写入 Hub 库；nonce 表只存哈希无关的随机挑战与公开字段。

## 6. 限制与遗留问题

- **SQLite 全链迁移**：历史迁移 `b4e8c7a92f10` 在 SQLite 上不支持（`create_check_constraint` 非 batch）。这是既有问题，本迁移自身在 SQLite 上已验证可往返；生产走 PostgreSQL，全链已在 PG 验证。
- **`alembic check`（SQLite 合成库）** 报了 `sse_stream_leases` 表缺失——该表属于独立 `LEASE_METADATA`，不随 `Base.metadata.create_all` 建，非 m1 引入；PG 全库 check 无漂移。
- **nonce 签发配额**：全局限流器 5 次/5 分钟/IP 对合法并发核销过紧，已改用 `issue_nonce` 内每 (action,address) 32 个存活挑战上限 + 过期行清理。如需更强的 IP 级防护，建议后续在网关层加通用限流，而非复用 auth 锁定语义。
- PostgreSQL 本地实例通过 unix socket（`/tmp/pgsock`）启动，`mapr_m1_test` 为一次性测试库；不影响生产。
- 前端、worker 侧对新字段（`source`/`paused_at`/`settings_json`/新端点）的对接不在本批次范围。
