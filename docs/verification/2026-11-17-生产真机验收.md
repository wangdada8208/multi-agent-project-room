## 关键发现与处理

1. **shell 会话会收掉后台助手**：裸 `&`、`nohup` 在 exec 环境均被进程组清理回收；`setsid` 脱离会话后长驻稳定。install.sh 的 autostart 路径（systemd/launchd）在真用户机上不受此影响。
2. **owner 身份必须持久化**：`createUser()` 每次随机生成 XMTP 身份；首次建群后未存私钥导致重启即失去群管理权，已改为 `owner-key.txt`（0600）落盘复用，废弃了首个群 `c4228afd...`。
3. **Claude Code CLI 不能回话是机器凭证问题**：引擎正确调起 `claude -p`，返回 `Not logged in · Please run /login`；本机 `/data/.claude/.credentials.json` 仅 15 字节无有效登录。这是验收机环境限制，非产品缺陷。改用 webhook 引擎（系统支持的第二种 Agent 类型）+ 本机模型网关完成「真模型回复」验证。
4. **webhook 引擎回路验证明确**：助手对 `{prompt}` 做 HMAC-SHA256 签名放 `X-MAPR-Signature` 头；应答端验签通过才放行——签名链路真实生效。

## 未覆盖项

- **浏览器本地网络权限弹窗**：Chrome 向 `127.0.0.1:8790` 发请求前的「本地网络访问」授权提示，只能在真实浏览器（用户机器）上确认；本验收为无头 API 驱动。
- **Claude/Codex CLI 端到端真回话**：等验收机上有可用的 claude 登录态（或 `ANTHROPIC_API_KEY`）后，重复 `@Claude Code ...` 即可复测，无需改代码。
- **install.sh 一键路径**：本次为手动等价步骤（同脚本逻辑分步执行）；脚本本体在 PR #10 CI 中有 shellcheck 与打包测试覆盖。
