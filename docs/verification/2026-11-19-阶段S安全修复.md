### 复审发现 → 实际修复

- **「member_revoked 可伪造」**（复审高危）：S2 只在收到广播后重拉 members()，但**没有校验会话必须是本房
  active group**——DM 或别的群里的伪造广播也能触发核实；且只清了 `policy.allow`+白名单内存，
  `policy.rules.actors`、持久化撤销、requester 的待批项都没清，重启可恢复。
  → 新增 `revocations.ts`：`applyMemberRevoked` 先查「会话==本房 activeGroupId 且 isGroup」，
  DM/其它群一律 `ignored_context` 不核实不清；核实前 `sync()` 再读 `members()`，目标仍在 ⇒
  `unconfirmed`（不清）；确认缺席才清 `policy.allow`、`policy.rules.actors`、白名单数组，
  并把撤销写进 `revoked.json`（0600）——启动时 `revokedStore` 参与发送者过滤，重启不恢复；
  requester 名下 pending 项批量置 `denied`；request_id 去重+每地址 15s 核实限速；
  unconfirmed/rate_limited 进 `RevocationRetries`（上限 5 次退避，超限记 `stalled`）。
  `member_revoked` 账本条目记 `sender`（广播者）与 `peer`（被撤对象）。
- **「出站请求无登记，响应可被伪造」**（复审高危）：S2 时 `action_result`/`disclosure` 只验签，
  攻击者偷看 request_id 后自签 grant 即可存入收件箱。
  → 新增 `outgoingRequests.ts`（0600 原子写）：ownerConsole 的 sendRequest/sendTask 与回执路径全部登记
  `{request_id, to, kind, scope/action, params_hash, expires_at}`；四类响应逐一匹配，
  首个终态响应胜出、重复幂等。详见 WP1 文档 R0 节。
- **「邀请吊销与 redeem 存在读写删竞态」**：S3 的吊销是「get→查 used_at→delete」三步，
  并发 redeem 可在检查与删除之间提交，把审计行删掉。
  → `invites.py` 改为原子条件删除 `DELETE ... WHERE token=? AND used_at IS NULL`，
  `rowcount!=1` 即回滚并 409——并发 redeem 先提交时吊销方得 409，审计链不断。
- **「XMTP 房可经 Hub Approval API 写自由文本」**：`POST /rooms/{id}/approvals` 对
  `transport="xmtp"` 的房会存 title/description 明文进 Hub 库。
  → 该路由在 404→403 之后对 xmtp 房直接 409 `body_not_on_hub`；hub 传输房原行为不变；
  历史已存数据不删除（list/approve 读路径不受影响）。

### R0 第三轮收敛（会话作用域撤销与启动顺序）

独立复审的高位问题「伪造群撤销可误清 DM 授权」先以回归测试复现：旧实现执行后
`policy.allow[VICTIM]` 从 `["task.run"]` 变成 `undefined`。本轮从状态模型修正，不再给全局清除逻辑加补丁：

- `RevocationStore` 以 `conversation_id + address` 为键。确认某地址不在本房 active group 后，只写该群撤销记录，
  只取消该群 requester 名下 `pending/approved` 项；不再删除 `policy.allow`、`policy.rules.actors` 或
  `allowedSenders`，也不取消 DM/其它群审批。`executing/awaiting_receipt` 保留真实执行状态，但同群回执发送与
  重发会按 `conversation_id` 检查撤销；其它会话回执不受影响。
- 删除 `startupPending/gateRestored/allows` 特殊启动门禁。撤销待核队列只负责后台对账，不再把一次群撤销提示
  变成跨会话、可永久滞留的发送者黑名单。
- 新增 `isSenderAuthorized`：DM 仅看显式授权且不调用 `members()`；群消息无论来自显式白名单还是
  `allowGroupMembers`，都必须通过当前群成员检查。成员读取失败、空表或畸形成员行均 fail-closed；
  未授权发送者不触发成员查询。收到撤销提示先失效该群缓存；旧撤销地址重新入群时强制刷新成员表，
  确认 present 后只解除该群旧撤销，持久化失败仍拒绝。
- `RevocationReconciler` 只处理持久化待核项，保持 single-flight、有界退避与 stalled 低频复查。
  首次后台核对移动到 `await agent.start()` 完成之后，既有 30 秒 timer 也由 `revocationReady` 防护，
  因此 XMTP `sync/members` 不再阻塞消息流启动。

本轮新增/更新回归覆盖：群撤销保留 DM 授权与 DM 待批、同群 pending/approved 取消、其它会话回执可重发、
群白名单但非当前成员拒绝、成员查询失败拒绝、DM 零成员查询、未授权发送者零成员查询、重入群强制刷新并
只清同群撤销、撤销记录落盘失败 fail-closed、后台重试 single-flight 与 stalled 后恢复。
