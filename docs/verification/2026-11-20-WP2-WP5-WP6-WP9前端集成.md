## 实现内容

### 1. L3：XMTP 发送幂等键（`xmtpSend.ts`）

- 新增 `defaultIdempotencyKey(parts)`：优先 SHA-256，回退 FNV-1a，输出 `mapr-<hex>`。
- `sendXmtpMessage` / `sendXmtpReply` 自动按 `groupId + content`（回复含 `referenceId`）派生确定性 `idempotencyKey`，传入 `sendText(content, { idempotencyKey })`；支持显式 `idempotencyKey` 覆盖。
- 效果：发送结果不明后的人工重试不会向群里写重复消息（在 SDK 支持该选项时；不支持时静默回退原行为）。

### 2. WP6：EIP-191 签名与内存解锁会话（`xmtpLocalIdentity.ts`）

- 新增模块级 `unlockedPrivateKey`（仅存内存，不进 DOM/localStorage/Hub）及 `setUnlockedXmtpKey` / `clearUnlockedXmtpKey` / `hasUnlockedXmtpKey` / `unlockedXmtpAddress` / `signXmtpMessage`。
- `signXmtpMessage` 在身份未解锁时抛出友好中文错误；解锁时用 `viem` 的 `privateKeyToAccount().signMessage({ message })` 产生 EIP-191 签名。测试用 `recoverMessageAddress` 验证可恢复出正确地址。

### 3. API 客户端（`api.ts`、`localHelper.ts`、`types/chat.ts`）

- `api.ts`：`FORBIDDEN_SCOPE_PREFIXES`/`FORBIDDEN_SCOPES`/`SCOPE_PATTERN`/`scopeIsForbidden`/`sanitizeScopes`（前端预检，后端仍是权威）；`HouseRules`/`RoomSettings`/`RoomTemplateInfo` 类型；`createRoomFromTemplate` 支持 `house_rules`/`team_config_markdown`/`default_max_rounds` 覆盖；`updateRoomSettings`（`PATCH /rooms/{id}/settings`，403/404 友好文案）。
- `localHelper.ts`：席位 `pause`/`resume`（Hub + 本机助手双通道）、`createRoomInvite`（`max_uses`/`requires_approval`/`role`/`proposed_scopes`/`expires_hours`）、`listRoomInvites`、`revokeRoomInvite`（DELETE）、`issueSignatureNonce`（`POST /invites/nonce`）、`redeemRoomInvite`（EIP-191：`xmtp_address` + `nonce` + `signature`，返回含 `status` 的 redemption）、`bindMyXmtpAddress`（`PUT members/me/xmtp-address`）、`listRoomRedemptions`/`approveRedemption`/`denyRedemption`、`removeRoomSeat`、`removeRoomMember`。
- `types/chat.ts`：`Room` 增加 `settings_version`、`settings_json`（注释注明 GET 不回读，仅建房/PATCH 回包携带）。

### 4. 群主同步第三趟与新核销源（`seatGroupSync.ts`）

- `syncPendingSeatsToGroup` 新增 `isRoomOwner`：房主客户端额外拉起 `source === "invite" && group_status === "pending"` 的云端席位（它们没有本机助手）。
- 新增 `collectGroupSyncAddresses`：汇总已 `approved`/`consumed` redemptions 的地址 + 成员行 `xmtp_address` + 旧邀请 `redeemed_by_address`；**绝不包含 pending/denied 核销地址**。
- `syncRedeemedInvitesToGroup` 改为接收 `listAddresses` 回调（由 RoomPage 组装三个来源）。
- 新增 `removeAddressFromXmtpGroup` + `memberRevokedNotice`（MAPR1 信封广播）。

### 5. 房主控制台客户端（`ownerConsole.ts`，新）

- `OWNER_HEADER = "X-MAPR-Owner"`；`ownerConsoleUrl`/`ownerConsolePageUrl` 只生成 `http://127.0.0.1:{port}` 回环地址。
- `fetchOwnerConsoleState` / `fetchConsentDetail` / `decideOwnerConsent`（`approve|deny|resend`）对齐 `workers/xmtp-member/src/ownerConsole.ts` 路由；网络失败映射为「无法访问本机审批控制台」的诚实错误。

### 6. 成员面板（`MembersPanel.tsx`）

- 席位徽章：`已暂停`（`paused`）、`云端`（`source === "invite"`）。
- 暂停/恢复按钮：仅席位属主或房主可见；同时调用 Hub 端点与本机助手（助手不可达时如实提示并仍完成 Hub 侧状态）。
- 移除顺序保持 S2 不变量：先 `removeAddressFromXmtpGroup`、成功后才 `removeRoomSeat`；`group_status === "pending"` 的席位跳过 XMTP 步骤；无权执行群管理时给出诚实提示，不删 Hub 行。

### 7. 权限面板（`PermissionsPanel.tsx`）

- 成员移除 S2 不变量：`planMemberRemoval`（纯函数）→ 有 `xmtp_address` 且为合法地址时必须「先出群、后删行」，失败/未解锁/无群主权限时给出诚实文案且不删 Hub 行；无地址成员需二次确认。
- 绑定我的加密地址：本机身份已解锁且与成员行地址不一致时，`nonce → signXmtpMessage → PUT` 一键绑定。
- 可复用邀请表单：`max_uses`(1–32)、`requires_approval`、`role`、建议 scope 勾选 + 自定义输入（`sanitizeScopes` 预检剔除硬禁项）、生成链接、邀请列表 + 吊销。
- 房主待批准队列：`GET redemptions?status=pending` 列表 + 批准/拒绝。
- 房间规则建议编辑器：`house_rules`（scope → ask/cannot + notes）经 `PATCH settings` 整体保存；`settings_json` 无法回读时如实提示「保存会整体覆盖现有建议」。

### 8. 房主审批面板（`OwnerApprovalPanel.tsx`，新）

- 侧栏新增「审批」页签（`roomTabs.ts` 增加 `"approvals"`，`RoomPage.tsx` 接线）。
- 仅连接各席位本机审批控制台（`listLocalSeats` → `consolePort` → `fetchOwnerConsoleState`），带 `X-MAPR-Owner` 头；控制台不可达时如实提示并给出 `http://127.0.0.1:{port}` 直达链接。
- 卡片展示 scope、用途、发起方、`rule_hit`、`source`（触发器徽章）、`account_id`、到期时间、执行状态与回执；详情按钮拉取 `params`（收件人/主题/正文等真实参数，只在本地展示）；支持批准/拒绝/重发回执；`uncertain` 状态给出「结果不明，需人工对账」提示，不自动重试。

### 9. 邀请核销升级（`RoomPage.tsx`）

- `?invite=` 自动核销改为签名流：`issueSignatureNonce → signXmtpMessage → redeemRoomInvite`。
- `status === "pending"` 时展示「等待房主批准」卡片；`consumed` 保持原「等待入群」自动轮询。
- `XmtpUnlock` 解锁后把私钥登记进内存会话（离开房间即清除），供绑定/核销签名使用。

### 10. 模板预览与覆盖（`TemplatePreview.tsx` 新、`HomePage.tsx`、`SetupPage.tsx`）

- `TemplatePreview`：只读渲染 `house_rules`（scope → 中文标签 + notes）、`team_config_markdown`（折叠 Markdown）、`default_max_rounds`，并明示「仅是建议，本机规则才是权威」。
- HomePage 建房弹窗：选中模板即显示预览；可展开「自定义此房间的配置与规则建议」编辑 scope 行、分工 Markdown、轮次上限，作为 `create-room` overrides 提交（未自定义则不带 overrides，用模板预置值）。
- SetupPage 场景选择：每个模板卡片增加「预览预置内容」开关；第三步席位同步传 `isRoomOwner`（建房人即房主）。

## 已知限制

- `GET /rooms/{id}` 不回读 `settings_json`，权限面板的规则编辑器无法预填既有建议；已在 UI 如实标注「保存将整体覆盖」。既有建议仅能通过建房回包或 PATCH 回包获得。
- 审批控制台仅允许回环来源：当浏览器与运行 Agent 的本机助手不在同一台机器时，面板如实降级为「请在该机器打开本机审批控制台」链接，不伪造可达性。
- `idempotencyKey` 依赖 `@xmtp/browser-sdk` 的 `sendText` 选项支持；不支持时按原样发送（无幂等保证），已注释说明。
