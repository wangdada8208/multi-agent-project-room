## 实现内容

### 1. `frontend/src/lib/encryptedDrafts.ts`（新）— 加密草稿

- 草稿按 `(roomId, identityAddress)` 隔离，storage key 形如 `mapr-draft-v1:<roomId>:<address 小写>`。
- 加密：WebCrypto AES-GCM-256；密钥由 HKDF 派生——密钥材料 = 内存中的已解锁会话秘密（XMTP 私钥或 Hub 登录令牌），salt = 身份地址，info = 房间 ID。密钥材料只存在模块级内存变量（`setDraftSessionKeyMaterial`），不落盘。
- `saveEncryptedDraft` / `loadEncryptedDraft` / `clearEncryptedDraft`：锁定时保存返回 false、读取返回 null 但保留密文（解锁后仍可恢复）；密文损坏或密钥不匹配时读取返回 null 并清除残损条目；存空串等价于清除。
- localStorage 中只出现 `{v, iv, ct}`（hex），测试断言明文子串不出现在存储值里。

### 2. `frontend/src/lib/xmtpSearch.ts`（新）— 本机内存搜索索引

- `XmtpSearchIndex`：`upsert`/`ingest`（按 id 去重）+ `search(query, {senderInboxId, limit})`，大小写不敏感子串匹配 + 发送者过滤 + 时间升序。
- 有界：默认最多 2000 条（`XMTP_SEARCH_MAX_ENTRIES`）、最多 7 天（`XMTP_SEARCH_MAX_AGE_MS`），超限先清过期再按最旧淘汰。
- `extractXmtpMessageText(message)`：纯文本直通；`EnrichedReply`（SDK `DecodedMessage.content = {referenceId, content}`）取内层文本并返回 `replyToId`；内层非文本回退 `fallback` 或「【暂不支持的消息类型】」；其余内容类型（附件/回执/群事件）返回 null 不索引。
- 不调用任何 Hub 接口、不写磁盘/localStorage；RoomPage 仅向其投喂 `group.messages()` 历史与流增量。

### 3. `frontend/src/lib/xmtpSend.ts` — 真实 `sendReply`

- 已核实 `@xmtp/browser-sdk@7.1.0` 真实 API：`Conversation.sendReply(reply: Reply, opts?: SendOpts)`，`Reply = {content: EncodedContent, reference: string, referenceInboxId?}`；回复经 `EnrichedReply` 解码（`referenceId`/`content`/`inReplyTo`），`isReply`/`isTextReply` 为纯 JS 判定。
- 新增 `sendXmtpReply({groupId, content, referenceId, referenceInboxId, fallbackQuote, client})`：内层文本用 `encodeXmtpText` 手工构造标准 `xmtp.org/text:1.0` EncodedContent（type + `parameters:{}` + UTF-8 bytes，与 SDK TextCodec 产物一致，避免在可测层引入 WASM 初始化）；会话缺 `sendReply` 时退化为「↩ 引用行 + 正文」普通文本。
- `sendXmtpMessage` 与 `sendXmtpReply` 共用一个会话解析函数（先查本地、未命中 `syncAll()` 一次再查，找不到抛错），行为不变。

### 4. `frontend/src/components/ChatInput.tsx` — 多行 + 草稿 + 回复 + 重试

- `<input>` 换成 `<textarea rows=1>`，随内容自适应高度（封顶 160px 内部滚动）；Enter 发送、Shift+Enter 换行、`nativeEvent.isComposing` 期间绝不发送（IME 安全）。
- 草稿：props 收 `roomId`/`identityAddress`/`draftKeyMaterial`；会话密钥 effect 声明在加载 effect 之前保证顺序；身份未解锁时不读也不写（防止锁定态把密文清空）；解锁且地址就绪后恢复草稿；成功后 `clearEncryptedDraft`。
- 回复：`replyTarget` 时顶部渲染「回复 <发送者>：<摘录>」横幅 + X 取消（`onCancelReply`）。
- 失败重试：`attemptSend` 统一判定 sent/failed/skipped；失败时显示红点错误条 + 「重试」按钮，输入框文字原样保留，`sending` 态防重复提交。
- 新增 `ChatInput.css`（组件内联样式块，沿用既有组件级 CSS 约定）。

### 5. `frontend/src/pages/RoomPage.tsx` — 接线

- `RawXmtpMessage` 增 `replyToId`；`toRawEntry` 改用 `extractXmtpMessageText`，回复消息展示内层文本（MAPR1 信封仍经 `describeEnvelope` 解码）。
- 消息行：被回复消息在气泡上方显示「↩ 回复 <发送者>：<摘录>」（引文缺失时显示「一条消息」）；每条非系统消息右侧挂小型回复钮（仅加密房、非观察者），点击置 `replyTarget`。
- `handleSend`：有回复目标时走 `sendXmtpReply`（referenceId = XMTP 消息 id、referenceInboxId = 原作者 inboxId），发送成功才清 `replyTarget`，失败保留横幅与草稿。
- 搜索：搜索按钮对全部房间显示（原先 `!isEncrypted` 隐藏）；`handleSearch` 在 `isEncrypted` 分支直接查 `xmtpSearchIndex`，**代码路径上不可能发出 Hub 搜索请求**（`searchMessages` 只在非加密分支执行）。搜索栏对加密房增加发送者过滤下拉（inboxId → 已解析显示名）并在结果标题注明「本机加密搜索」。
- `xmtpSearchIndex` 按 `room?.xmtp_group_id` memo 重建；`ChatInput` 收到 `roomId`、加密房 `identityAddress=myXmtpAddress`/Hub 房 `user.id`、加密房 `draftKeyMaterial=unlockedKey`/Hub 房登录令牌。

## 边界与如实声明

- **回复协议**：蓝图「存消息 meta」的方案落空后，按修订意见采用 SDK 原生 `sendReply`（7.1.0 已带 Reply codec）。旧端（不含 reply codec 的客户端）显示 SDK fallback 文本；本端对非文本回复显示 fallback 或「暂不支持」。
- **Hub 房草稿**：与加密房共用加密草稿通道，密钥材料是 `mapr-auth-token`——因令牌与密文同在 localStorage，对窃取本机存储者不构成防护，仅满足「不写明文草稿」。加密房用 XMTP 私钥派生，是真密钥分离。
- **重试不重复**：靠失败保留草稿 + `upsertRawBatch` 按消息 id 去重实现；XMTP `SendOpts.idempotencyKey` 未接线——若首条实际已上网但响应丢失，重试仍可能产生网内重复（SDK 默认按时间戳生成 key）。列入后续。
- **未做**：浏览器真机点击流、双机 XMTP 真网互发回复、搜索大房间性能实测；`ChatInput` 交互（真实 DOM 事件）超出当前 vitest 无 DOM 环境，只做到结构级 + 纯函数级断言。
- 未提交、未推送、未合并 main、未部署。
