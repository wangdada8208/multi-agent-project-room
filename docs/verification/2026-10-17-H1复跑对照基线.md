## 二、三个脚本的原样输出（后端侧基线）

### 1. accept_grep_zero.py —— 组长定的验收标准

```text
$ ./.venv/bin/python scripts/verify/accept_grep_zero.py
日志总行数: 1474   sqlalchemy.engine 行数: 261
grep invite: 0 行
grep share: 0 行
总结：通过
退出码=0
```

判读要点：**`sqlalchemy.engine 行数` 必须大于 0**。如果是 0，说明这个服务根本没跑过
带参数的数据库查询，那种"0 行泄露"是假绿，不算数。

### 2. verify_h1_full.py —— 三种场景

```text
$ ./.venv/bin/python scripts/verify/verify_h1_full.py
[真实服务(访问日志 + DEBUG)] 日志 12 行, 泄露 0 行 -> OK
[引擎 echo=True] 日志 690 行, 泄露 0 行 -> OK
[引擎 echo=False] 日志 715 行, 泄露 0 行 -> OK
总结：全部拦住
退出码=0
```

`echo=True` 与 `echo=False` 都测了：前者是 SQLAlchemy 自己打参数日志，
后者是靠 `sqlalchemy.engine` logger 的 DEBUG。两条路径都覆盖。

### 3. repro_h1_db_params.py —— 组长那支探针的同款

```text
$ ./.venv/bin/python scripts/verify/repro_h1_db_params.py
令牌长度: 43   日志总行: 1159   泄露行: 0
总结：未泄露
退出码=0
```

使用的是真实格式令牌（`secrets.token_urlsafe(32)`，43 位），不是手写的短串。

## 三、行数会轻微浮动

日志行数与 SQLAlchemy 首次编译、缓存命中等有关，不同次运行会在 1000～1500 之间浮动，
这属正常。**只有"泄露行 = 0"和"引擎行数 > 0"这两个判据是硬指标**，
不要按行数是否完全一致来判通过与否。
