## 交付内容

### 1. 多账户登记（accounts.ts）

- `.state/accounts.json` 只存 `{id, service:"gmail"|"google_calendar", label, cred_path}` 四字段；
  `normalizeEntry` 白名单剥字段——即使有人手工往文件里塞 token，load/add 都会丢弃。
- `id` 限 `^[a-zA-Z0-9._-]{1,64}$`；`cred_path` 限纯文件名 `*.json`，
  `resolveCredentialPath` 再纵深校验 resolve 后必须严格落在凭据目录内（拒绝 `../`、绝对路径）。
- `verifyCredentialFile` 在加载凭据前强制：realpath 不得越出凭据目录（符号链接逃逸）、
  必须真实文件、权限必须恰为 `0600`；任一不满足抛错，调用方按 `auth_required` 收口。
- 写入走 `secureFile.writeJsonSecure`（0700 目录、0600 原子写 + fsync + 串行写锁）。
- 损坏的 `accounts.json`（非数组、条目非法、id 重复）一律 fail closed 拒绝加载。

### 2. 连接器多账户路由（connectors/*）

- `Connector` 新增 `accountId?: string`；`ExecuteContext` 新增 `account_id`。
- `findConnector(connectors, scope, accountId?)`：
  - 指定 `accountId` 时**只**匹配 `accountId` 完全一致的连接器——未绑定连接器绝不替绑定请求执行；
  - 未指定时保持旧行为（首个 scope 匹配），`accounts.json` 不存在时 100% 向后兼容。
- `GmailSendConnector` / `GmailReceiptConnector` / `GoogleCalendarConnector` 接受 `accountId`；
  `gmailSend.execute` 校验 `context.account_id === this.accountId`，不符直接 `failed:unknown_account`。
- `index.ts` 为 `accounts.json` 中每个账户按 service 挂载 accountId 绑定的连接器；
  `cred_path` 非法的账户不挂连接器，路由自然落空为 `no_connector`。

### 3. 批准与执行的账户绑定（consentActions.ts / handleEnvelope.ts）

- 入队时 `account_id` 取自 `params.account`；`account` 键本身就在 `params_hash` 覆盖范围内。
- `runApprovedAction` 执行前一致性校验：`params.account` 与批准时记录的 `account_id` 必须一致，
  队列文件中任一被改（掉包账户）都按篡改拒（`action_tampered` 终态 + 账本），不放回待批。
- 找不到与 `account_id` 匹配的连接器时释放批准回 `pending`（`no_connector`），绝不退到其他账户的凭据执行。

### 4. Gmail 增量事件触发器（triggers.ts）

- `.state/triggers.json` 经 `writeJsonSecure` 落盘（0700 目录 / 0600 文件）；
  每条 = 配置（`id, enabled, account_id, query, action, action_params_template, max_per_hour, poll_interval_ms`）
  + 运行态（有界 `seen_ids` ≤500、`last_history_id`、`last_poll_at`、小时窗口 `window_start/window_count`、
  `consecutive_failures`、`next_poll_at`）。损坏文件 fail closed。
- 轮询：有 `last_history_id` 走 `history.list?startHistoryId=&historyTypes=messageAdded`（分页上限 3 页）；
  游标过期（404）清游标下轮回退 `messages.list?q=`；首轮从 `messages.get?format=metadata` 取 historyId 当新游标。
- 去重键 `${account_id}:${external_event_id}`；限频命中时**不标已见、不推游标**——剩余事件下个窗口还会回来。
- 失败退避：`next_poll_at = now + poll_interval_ms × 2^(failures-1)`（封顶 1h），`pollDue` 对未到期的触发器跳过。
- 安全不变量（每个候选事件必经）：
  `decide(rules, policy, {actor:self, kind:"action", scope})` → `validateActionParams` →
  `queue.add({source:"trigger", requester:self, conversation_id:"", params_hash, rule_hit, account_id})` →
  `allow` 时走与人工完全相同的 `approveConsent` 执行路径。
  - 默认 ask → 留 `pending` 等人工；`cannot`（含硬禁区）→ 记 `request_denied` 账本并标已见；
  - 参数模板校验失败 → 同上拒；
  - `params.account` 渲染后被强制写回触发器自己的 `account_id`——模板不能替别的账户发起绑定；
  - 触发器不产生隐式 allow、不绕过审批队列；`conversation_id === ""` 时执行路径跳过 XMTP 发送，
    但队列状态、账本、`auto_approved`/`action_finished` 与本地 inbox `action_result` 照常落地；
  - 创建时 `validateAndCheckTrigger` 同样先 `decide()` 再探模板——硬禁区 scope 在 POST 阶段即被拒。

### 5. 主人控制台扩展（ownerConsole.ts / ownerConsoleHtml.ts）

- `GET /api/accounts`（owner 头，只回四字段元数据）、`POST /api/accounts`（写 0600 凭据文件，
  凭据写失败回滚账户行）、`DELETE /api/accounts/:id`（删登记 + 尽力清凭据文件）。
- `GET /api/triggers`（`seen_ids` 不回传只给条数）、`POST /api/triggers`（`validateAndCheckTrigger` 全程校验）、
  `POST /api/triggers/:id/toggle`（翻启停并回调引擎刷新）；账户/触发器写操作 observer 一律 403。
- `GET /api/activity`（localGuard 回环保护）：`actor/kind/status/since/until/limit` 过滤，
  返回 `{entries, total, integrity}`，`integrity` 来自文件级 `verifyLedger`（含 malformed 行检测）。
- 控制台页面：审批卡显示「（由触发器发起）」徽标与「绑定账户：<label>」；
  新增「外部账户」「事件触发器」管理区（登记/删除/启停/状态一览）；observer 角色隐藏全部写区。

### 6. index.ts 接线

- 启动时加载 `AccountStore`/`TriggerStore`，为登记账户挂 accountId 绑定连接器；
  `TriggerEngine` 复用同一套 `ConsentActionDeps`/`approveConsent`；
  `onTriggersChanged` 回调 `engine.refresh()`；`agent.start()` 后 `refresh()` 按需起巡检，
  SIGINT/SIGTERM 停表。无启用触发器时不起任何定时器。

| 需求 | 证据（测试名 / 断言） |

## 遗留说明

- `history.list` 404（游标过期）记一次失败并清游标，下一轮才回退 `messages.list`——
  选择不在同一轮立即重试，避免陈旧游标与全量列表混读；行为已固化进测试。
- 触发器只支持 `gmail` 账户的事件源；`google_calendar` 账户可登记但暂不参与轮询
  （创建时 `account_not_gmail` 拒绝非 gmail 账户绑触发器）。
- 控制台页面内联脚本按既有模式携带 `X-MAPR-Owner: 1`（回环 + origin 校验才是防线），未改动该模型。
