## 2. 做了什么

### `SYSTEM_TEMPLATES` 扩展（`backend/app/api/templates.py`）

- 每个系统模板新增三个元数据字段：
  - `house_rules`：结构化信封 `{"scopes": {scope: "ask"|"cannot"}, "notes": [str]}`。只含保守建议——评审/讨论类模板把 `gmail.send` 建议为 `cannot`（远端只收紧），其余注册 scope 一律 `ask`。绝不出现硬禁区 scope（`payment.`/`banking.`/`credentials.`/`password.`/`card.`/`wallet.` 前缀与 `data.export_all`），绝不出现 `allow`（远端元数据不能自动放权，B5）。
  - `team_config_markdown`：保留原有角色/协作说明，统一前置非权威声明行「> 说明：本配置仅为协作建议，不构成授权依据；本机规则与主人批准永远优先。」，使文本在任何注入点（prompt、群公告）都自证非授权依据。
  - `default_max_rounds`：可选整数（1..64），dev_team 为 3（对应「三轮无法达成共识时升级给人类」）。
- `house_rules`/`default_max_rounds` **没有**新增数据库列（本任务不碰 models/alembic）：它们是代码定义的常量，读取时按 `key` 叠加到 `RoomTemplate.to_dict()` 上；`seed_system_templates` 只把实际列名过滤后写入 `RoomTemplate`，旧库重复 seed 仍幂等。

### `GET /api/v1/templates`

- 响应每项干净透出 `house_rules`、`team_config_markdown`、`default_max_rounds`；DB 行中无对应常量的 key 返回 `null`。

### `POST /api/v1/templates/create-room`

- 请求体新增**可选**主人覆盖项：`house_rules`（dict）、`team_config_markdown`（≤4096 字符）、`default_max_rounds`（1..64）；`extra="forbid"`。
- 组装 `{template_key, house_rules, team_config_markdown, default_max_rounds}` 写入 `room.settings_json`，`settings_version = 1`；响应 `room` 附带 `settings_json`。
- 校验与 `PATCH /rooms/{id}/settings`（rooms.py）完全同规：JSON 可序列化、序列化后 ≤8 KiB、`*scope*` 命名键下的字符串走 `validate_scope_list`、无 scope 键时对裸字符串做禁 scope 兜底扫描（复用 `app.api.rooms._settings_scope_strings` / `_MAX_SETTINGS_BYTES` 与 `app.api.invites.scope_is_forbidden` / `validate_scope_list`）。
- `house_rules` 语义校验（`_validate_house_rules`）：信封仅允许 `scopes`/`notes` 两键；scope 键过硬禁与格式校验（`*` 作为 worker 侧兜底键放行）；裁决值只许 `ask`/`cannot`，`allow` 一律 422；notes ≤32 条、每条 ≤280 字符。

## 5. 遗留（如实记录）

- `house_rules`/`default_max_rounds` 仅存于代码常量：DB 中 `room_templates` 行不携带它们，列表/建房靠常量按 `key` 叠加。若未来允许自定义模板携带这两项，需新迁移加列（需人类批准）。
- worker 侧消费未在本包范围：`house_rules` 经心跳 `rooms` 下发后，worker 的「allow 降格 ask、cannot 生效、本机 > Hub > 出厂」合并与 `team_config_markdown` 注入 prompt 属 WP9 worker 部分，待交付。
- `house_rules.scopes` 目前是 scope→裁决的扁平映射，不含 per-actor `actors` 覆盖（模板不知道成员地址，合理）；`"*"` 键被允许但模板默认未使用（出厂默认已 `"*"→ask`）。
- `PATCH /rooms/{id}/settings`（rooms.py）尚不认识 `house_rules` 信封形状——它只做通用禁 scope 校验，不会拒绝 `allow` 值；语义校验目前只在模板建房路径。如需统一收紧，属后续小提案。
