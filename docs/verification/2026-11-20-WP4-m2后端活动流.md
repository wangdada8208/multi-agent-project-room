## 2. 做了什么

### m2 结构迁移 `m30c20261120`（`backend/alembic/versions/m30c20261120_m2_activity_events.py`）

- `activity_events`：helper / 云端 Agent 上报的**安全元数据**事件。列：`id`（上报方生成、主键即幂等键）、`room_id`（FK → rooms，CASCADE）、`actor_kind`（CHECK `human|agent|helper|system`）、`actor_id`、`kind`、`app`、`status`、`subject_id`、`stream_seq`、`reported_by`、`created_at`。索引 `(room_id, created_at DESC)`、`(room_id, actor_id, created_at DESC)`、`(room_id, kind, status)`。**硬红线：无 `payload`/`content`/`params_hash`/`digest` 列。**
- `activity_checkpoints`：worker 本地账本链头的 EIP-191 签名锚点。列：`id`、`room_id`（FK → rooms，CASCADE）、`stream_id`、`signer_address`、`head_seq`（CHECK ≥0）、`head_hash`、`entry_count`（CHECK ≥0）、`signature`、`reported_by`、`checkpoint_at`、`created_at`。唯一约束 `(room_id, stream_id, head_seq)`，索引 `(room_id, stream_id, head_seq DESC)`。
- 仅 `create_table`/`create_index`，SQLite 与 PostgreSQL 同一代码路径执行。

### 后端活动流 API（`backend/app/activity/`）

- `POST /api/v1/helpers/me/activity`（helper token）：helper 主人必须是每个事件所在房间的 owner/member；`actor_id` 必须属于该 helper 的身份集（主人本人、helper 自身、主人在该房的 XMTP 地址、helper 在该房的席位及其 agent_user_id/agent_key/xmtp_address）。批次上限 100。
- `POST /api/v1/rooms/{room_id}/activity`（agent JWT）：agent 必须是该房成员或持活跃席位；事件 `room_id` 必须与路径一致；`actor_id` 必须是 agent 自身身份集。
- `POST /api/v1/helpers/me/activity/checkpoints` 与 `POST /api/v1/rooms/{room_id}/activity/checkpoints`：
  - 用 `eth-account` 重建 `workers/xmtp-member/src/activity.ts` 签名的消息并验签：`"MAPR1-LEDGER-CHECKPOINT " + canonicalJson(payload)`，其中 `payload` 只含 `version/room_id/stream_id/head_seq/head_hash/entry_count/created_at` 七字段（`signer`/`signature` 不进签名负载），`canonicalJson` = 键递归排序的紧凑 JSON（Python `json.dumps(sort_keys=True, separators=(",",":"), ensure_ascii=False)`，与 JS `JSON.stringify` 排序键输出一致）。`created_at` 以原始字符串保存并直接参与验签，不做 datetime 往返。
  - 签名者地址（校验和归一化后）必须是该房成员的绑定 XMTP 地址或活跃席位 XMTP 地址。
  - 单调性：`head_seq` 低于该 `(room_id, stream_id)` 已存最大值的 → 409 回滚；同 `head_seq` 不同 `head_hash` → 409 冲突；完全相同 → 幂等重复（计入 `duplicates`）。
- `GET /api/v1/rooms/{room_id}/activity`（viewer+）：合并 `activity_events` + Hub `task_events` + Hub `approvals` + 每条流最新签名锚点，按时间倒序截断到 `limit`（≤200）。过滤：`actor`、`app`、`kind`、`status`、`since`、`until`。
  - **XMTP 房间零正文泄漏**：审批标题一律不下发（`title=None`）；审批描述、任务 query/result、task_event payload 任何房间都不进本接口。非 XMTP 明文房间仅透出审批 `title`（成员本就能从审批 API 看到）。
- 幂等与并发：`event.id` 即幂等键——相同内容重发去重，同 id 不同内容 409；批内立即 `flush()`，批内重复 id 或跨事务竞争触发 `IntegrityError` 时整批回滚并返回 409「重试整批」，客户端幂等重发即收敛。检查点路径同构。整个批次原子：任一事件越权/冲突则整批不落库。
- 错误面：路由层捕获 `SQLAlchemyError` → 503 统一文案（不带 SQL 参数值）；业务校验失败 403/409/422 语义见测试。

### Pydantic 边界

所有入站 schema `extra="forbid"`：`payload`、`content`、`body`、`params`、`params_hash`、`digest`、`title`、`description` 等任何非白名单字段 → 422。白名单镜像 worker `SafeActivityEvent`（另加 Hub 元数据 `app`/`stream_seq`）；`head_hash`/`signer`/`signature`/`created_at` 格式校验与 worker `activity.ts` 同规则（64 位小写 hex、0x 地址、0x+65 字节签名、ISO-8601）。

### 模型注册

`backend/app/models/__init__.py` 原本为空文件，现 `import app.activity.models`——`import app.models` 后即完成注册，`alembic env.py` 与 `database.init_db` 的既有 `import app.models.*` 路径自动覆盖新表（PG 上 `alembic check` 已验证无漂移）。

## 4. 关键正确性核验点（由测试覆盖）

- 额外/正文字段（`payload`、`content`、`body`、`params_hash` 等）→ 422。
- 同一事件重发 → `accepted=0, duplicates=1`；同 id 不同内容 → 409。
- 跨房间事件、伪造 actor_id（helper 报他人、agent 报他人/他房）→ 403；批次超 100 → 422。
- 有效 EIP-191 检查点按 worker 格式验签通过；伪造签名 → 422；签名者非房间授权地址 → 403。
- 检查点回退（低于已锚 head_seq）→ 409；同 seq 异 hash → 409；完全重复 → 幂等。
- GET 合并三源 + 各流最新锚点，过滤生效；`limit` ≤200 由 Query 校验强制。
- XMTP 房间审批项 `title=None`、无任何描述/正文；明文房间仅 title 透出。
- 无聊天/邮件/动作正文、无可猜测参数摘要写入 Hub 库——表结构层面就不存在这类列。
