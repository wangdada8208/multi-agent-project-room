## S3 排查结论（重要）

- 实测确认：不加外层隔离时，`codex exec --sandbox read-only` 读得到家目录文件（金丝雀原样泄露）。
- bubblewrap 有效，且与 Codex 自身的沙箱嵌套运行正常（Codex 0.166 的 linux 沙箱本身就用 bubblewrap，Landlock 是回退）。
- 最终挂载模型是「先整根只读，再遮全部家目录，最后按白名单放行」：
  1. `--ro-bind / /` 保证系统库与运行时文件不缺。
  2. `--tmpfs /home --tmpfs /root`（家目录在 `/data` 这类非标准位置时也遮）。
  3. 放行：工具链目录与 arg0 辅助二进制目标（只读）、`CODEX_HOME`、空白沙箱、
     `MEMBER_AGENT_BWRAP_RW` 指定目录（可写）。
- 挂载顺序敏感：`--ro-bind / /` 必须最先，`--proc`/`--dev`/`--tmpfs` 其次，家目录 tmpfs 必须
  在放行挂载之前。
- 两个隐蔽依赖（按这个顺序排错，否则会拿到不带路径信息的 `os error 2`）：
  1. `$CODEX_HOME/tmp/arg0/codex-arg0*/` 里的辅助二进制是**软链**，指向安装包 vendor 目录；
     白名单模式下必须把软链解析后的目标目录补挂回去（`arg0HelperDirs` 做这件事）。
  2. Codex 可能依赖环境特有的可写目录。本机的 memoh 包装要求 `/data/magpie` 可写
     （模型网关状态目录），通过 `MEMBER_AGENT_BWRAP_RW` 透传，不写死在代码里。
- 没有 bubblewrap 时引擎在创建阶段直接抛错，绝不裸跑（方案 S3 的硬门槛）。
